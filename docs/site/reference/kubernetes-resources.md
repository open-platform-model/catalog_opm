The raw catalog, `opmodel.dev/catalogs/k8s@v1`, carries native Kubernetes APIs through as they are. It is the last resort: use one of its resources only for what the blueprints, resources and traits in [Catalog members](/docs/reference/catalog-members/) do not model. Each resource's API version mirrors the upstream Kubernetes API version it was adopted at, so `apps/v1` is `@v1` and `autoscaling/v2` is `@v2`. Neither catalog imports the other.
