## Why

The raw Kubernetes catalog (`opmodel.dev/catalogs/k8s@v1`) is being retired (owner decision, 2026-10-02; the removal is the change `retire-k8s-catalog`). The one capability worth keeping from it is the escape hatch: a module must still be able to ship an object no `opm` abstraction models, such as a custom resource instance (Issuer, IPAddressPool, ServiceMonitor) or a kind with no member here (StorageClass, CSIDriver, APIService). That gap was Tier 1 in `modules/catalog-migration-gap-analysis.md`.

The k8s catalog's answer validates almost nothing. Its `#ObjectsResource` is `{apiVersion!, kind!, ...}`, and its typed members wrap hand-written open (`...`) schemas. A typo in a field name reaches the cluster. The `opm` catalog already depends on `cue.dev/x/k8s.io` v0.12.0, which carries a closed definition for every built-in kind with a concrete `apiVersion` and `kind`. One resource can dispatch each object to its upstream definition and validate it at `cue vet` time. This change adds that resource before the k8s catalog goes, so there is no window without an escape hatch.

## What Changes

- **New member `objects@v1alpha1`** (`opm/resources/v1alpha1/objects.cue`): `#ObjectsResource`, its `#Objects` component wrapper and `#ObjectSchema`. A map of Kubernetes objects keyed by name, each rendered as written, one output object per entry.
  - **Validation.** An object whose `apiVersion` + `kind` is a built-in Kubernetes kind is unified with its closed `cue.dev/x/k8s.io` definition: an unknown field, a wrong type or a missing required field is refused. An unknown kind in a built-in API group (`apps/v2`) is refused. Any other kind (a custom resource) passes open.
  - **Name.** `metadata.name` defaults to the map key and is rendered exactly as written, never prefixed, so references between objects (`roleRef.name`, a backend's service name) hold.
  - **Namespace.** A namespaced kind gets the instance namespace unless the object sets one; a cluster-scoped kind refuses one. Scope comes from the kind table for built-in kinds and from a `#scope` definition field, never rendered, for any other kind, where it is required.
  - **Labels** are merged over the render context's labels (the object's value wins); annotations pass through as written.
- **New schema package `opm/schemas/kinds/`**: `table.cue`, a generated table `#Table: [apiVersion]: [kind]: {schema?, scope?}` covering `cue.dev/x/k8s.io` v0.12.0 and the Kubernetes v1.34.0 OpenAPI spec, plus a CUE self-consistency assertion that `cue vet` runs.
- **New transformer `objects-transformer`** (`opm/transformers/objects_transformer.cue`), listed in `catalog.cue` with the resource.
- **New maintainer tool `tools/kindgen/`** (Go, its own `go.mod`) and `task generate:kinds`, which regenerate the table when `cue.dev/x/k8s.io` is bumped. CI does not run it.
- **Docs.** `docs/site/authoring/use-a-raw-kubernetes-resource.md` is rewritten around `#Objects`; `docs/name-constraints.md` records the names-as-written carve-out.
- Nothing is **BREAKING**: every addition is new surface, at `v1alpha1`.

## Before / After

**Before**

```cue
// opm/resources/v1alpha1/objects.cue: none
// opm/schemas/kinds/table.cue: none
// opm/transformers/objects_transformer.cue: none
```

**After**

```cue
// opm/schemas/kinds/table.cue (generated by tools/kindgen; do not edit)
#Table: {
	"apps/v1": Deployment: {schema: apps_v1.#Deployment, scope: "Namespaced"}
	"rbac.authorization.k8s.io/v1": ClusterRole: {schema: rbac_v1.#ClusterRole, scope: "Cluster"}
	// In the OpenAPI spec but not in x/k8s.io: known scope, no schema.
	"certificates.k8s.io/v1": CertificateSigningRequest: scope: "Cluster"
	// ... about 100 kinds over 35 group-versions
}

// opm/resources/v1alpha1/objects.cue
#ObjectsResource: c.#Resource & {
	metadata: {
		name:       "objects"
		apiVersion: "v1alpha1"
		fqn:        "\(id.kindPrefix.resources)/objects@v1alpha1"
		// modulePath, catalogVersion, description, labels as every member
	}
	spec: objects: [Key=string]: #ObjectSchema & {metadata: name: string | *Key}
}

#Objects: c.#Component & {
	#resources: (#ObjectsResource.metadata.fqn): #ObjectsResource
}

#ObjectSchema: {
	apiVersion!: string
	kind!:       string
	metadata: name: string
	// Never rendered. Taken from the kind table for a built-in kind; required
	// for any other kind.
	#scope: "Namespaced" | "Cluster"
	...
	// Built-in kind: unify with its closed x/k8s.io definition and its scope.
	// Unknown kind in a built-in API group: refused. Otherwise: open.
}
```

A module author writes:

```cue
#components: extras: obj.#Objects & {
	spec: objects: {
		"web-reader": {
			apiVersion: "rbac.authorization.k8s.io/v1"
			kind:       "ClusterRole"
			rules: [{apiGroups: [""], resources: ["pods"], verbs: ["get"]}]
		}
		selfsigned: {
			#scope:     "Cluster"
			apiVersion: "cert-manager.io/v1"
			kind:       "ClusterIssuer"
			spec: selfSigned: {}
		}
	}
}
```

## Impact

- **Release class.** `feat(resources)`: `opm` is on its stable line (major `@v4`) and takes a minor, `4.5.0`. No member moves to a new `apiVersion` segment; the new member starts at `v1alpha1`, where alpha promises nothing (0010 D34).
- **`modules` fleet and `opm-modules`.** Nothing to do. None imports the k8s catalog (checked 2026-10-02). A module that needs a custom resource can adopt `#Objects` after it pins `4.5.0`.
- **Subscribing platforms.** A platform on `opmodel.dev/catalogs/opm@v4` gains the contract when it re-pins to `4.5.0`; nothing else changes.
- **`cli` fixtures under `testing.opmodel.dev`.** None reached.
- **Kernel.** The render must hand the transformer the component's `#scope` definition field; section 1 verifies that through `opm module build` before any member lands.
- **Ceiling.** Built-in kinds validate against Kubernetes 1.34 (x/k8s.io v0.12.0). A field added in a later Kubernetes is refused, and there is deliberately no per-object escape (owner decision, 2026-10-02). Raising the ceiling is an x/k8s.io bump plus `task generate:kinds`.

## Enhancement

None. No enhancement entry backs the k8s catalog's retirement or this replacement; the decisions are the owner's of 2026-10-02, recorded in design.md.
